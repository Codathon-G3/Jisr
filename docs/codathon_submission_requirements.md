# Ai4LY National Codathon 2026 — Submission Requirements & Scopes

**Competition:** Libya Artificial Intelligence Forum 2026 (Ai4LY) — National Codathon  
**Submission Method:** GitHub Project Repository Link  
**Submission Deadline:** **Wednesday, October 7, 2026, at 11:50 PM**  

---

## 1. Primary Submission Vehicle

* **GitHub Repository Link:** Every team must submit a single, complete GitHub repository link prior to the strict deadline of 11:50 PM. All deliverables below must be located within or accessible directly from this repository.

---

## 2. Core Deliverables & Scope Breakdown

### A. Source Code (`Source Code`)
* **Requirement:** Complete codebase of the solution.
* **Scope & Expectations:**
  * Must contain all implementation logic, scripts, configurations, and assets needed to execute the application or model.
  * Permitted technologies include open-source models, modern frameworks, and external APIs.
  * Code should be cleanly structured, commented where necessary, and adhere to standard engineering best practices.

---

### B. Project Documentation (`README.md`)
* **Requirement:** A root-level `README.md` file guiding users and evaluators through the project.
* **Scope & Expectations:**
  * **Project Architecture:** High-level overview and diagram/breakdown of the components, data flow, and backend/frontend/model interactions.
  * **Operational Requirements:** List of dependencies, system prerequisites, language/runtime versions, and necessary API keys or environment variables.
  * **Setup Steps:** Clear, step-by-step instructions to clone, install dependencies, and build the environment.
  * **Usage Instructions:** Commands and workflows to run, test, and interact with the application.

---

### C. Technical Report (`.md` Format)
* **Requirement:** A dedicated, in-depth technical report in Markdown format.
* **Scope & Expectations:**
  * **Problem Alignment:** Detailed explanation of how the project addresses the announced competition theme/sector.
  * **Technical Methodology & Architecture:** Detailed rationale behind algorithm selections, data pipelines, model choices, and tech stack trade-offs.
  * **Attribution & Citations:** Explicit disclosure and citation of all open-source models, pre-trained weights, APIs, third-party libraries, and dataset sources used (as mandated by Section 4).
  * **Evaluation & Impact:** Performance metrics, testing outcomes, limitations, scalability considerations, and future potential.

---

### D. Presentation (Pitch Deck) or Demo Video
* **Requirement:** Either a Pitch Deck file/link **OR** a Demonstration Video file/link included directly in the repository.
* **Scope & Expectations:**
  * **Option 1: Pitch Deck (Presentation File or Link)**
    * Covers problem statement, market/societal need, proposed AI solution, system demo snapshots, business/social impact, and team roles.
  * **Option 2: Demo Video (File or Link)**
    * A walkthrough demonstrating the working prototype in real time, explaining key features, UI/UX, and core AI model outputs.
  * **Location Scope:** Must be linked prominently in the `README.md` or added as an asset/file inside the repository (ensure permissions are set to public if hosting on Google Drive, YouTube, Loom, etc.).

---

## 3. Supplementary Administrative Requirements

Before or alongside project submission, teams must also satisfy the following administrative items:
* **Team Lead Appointment:** Must be agreed upon and submitted via the designated team group chat.
* **Contestant Emails:** Provide the email address of every team member to the organizers.
* **Event Representation:** In-person attendance on the event day is preferred (or an appointed representative) for the awards ceremony.
