## Signing: Debug Key, Sideloading Only

This APK is signed with the standard Android **debug** keystore generated by the Expo template, not a private release key.

- It installs and runs on any Android 6.0+ device or emulator by **sideloading** (see below).
- It is **not** suitable for the Google Play Store or any store distribution.
- Any APK signed with the same public debug key can be installed as an update over it, so treat it as a demo build only.

## Verifying the File

```bash
# Linux / macOS
sha256sum builds/jisr-v1.0.0.apk

# Windows (PowerShell)
Get-FileHash builds/jisr-v1.0.0.apk -Algorithm SHA256
```

The result must equal the SHA-256 in the table above. To check the signature with the Android SDK build tools:

```bash
apksigner verify --print-certs builds/jisr-v1.0.0.apk
```

## Installation (Sideloading)

### Option 1: Directly on the device
1. Copy `jisr-v1.0.0.apk` to the phone (USB, cloud drive, or direct download).
2. Open it from the **Files** / **Downloads** app.
3. If prompted with *"Install unknown apps"*, tap **Settings** and allow installs from that source.
4. Tap **Install**, then **Open**.

### Option 2: Android Debug Bridge (ADB)

```bash
adb devices
adb install -r builds/jisr-v1.0.0.apk
adb shell am start -n com.ai4ly.jisr/.MainActivity
```

## Building the APK from Source

### Prerequisites
- Node.js 20+
- JDK 17
- Android SDK with `platforms;android-34`, `build-tools;34.0.0`, `ndk;26.1.10909125`, `cmake;3.22.1` and `platform-tools`

### Expo Prebuild + Gradle (how this APK was built)

```bash
# 1. Install dependencies
npm ci

# 2. Generate the native Android project (android/ is git-ignored)
npx expo prebuild --platform android --no-install
# prebuild rewrites the "android"/"ios" npm scripts; restore them before committing:
git checkout -- package.json

# 3. Point Gradle at the SDK (forward slashes also work on Windows)
echo "sdk.dir=/path/to/Android/Sdk" > android/local.properties

# 4. Assemble the release APK
cd android
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a,armeabi-v7a,x86_64   # Windows: .\gradlew.bat ...
cd ..

# 5. Copy it into builds/
cp android/app/build/outputs/apk/release/app-release.apk builds/jisr-v1.0.0.apk
```

A first build downloads the Gradle distribution and Maven dependencies and takes 30+ minutes; later builds reuse the cache.

### EAS Build (needs an Expo account)

```bash
npx eas-cli build --profile preview --platform android
```

### GitHub Actions
`.github/workflows/build-apk.yml` runs the safety tests (`npm test`), builds the APK with Expo prebuild + Gradle, and uploads it with its SHA-256 as the workflow artifact `jisr-v1.0.0-apk`.

## Permissions & Privacy

Permissions declared in the APK manifest:

| Permission | Why it is there |
|---|---|
| `android.permission.INTERNET` | Optional stateless calls to the FastAPI backend (`/api/generate-drafts`, `/api/faithfulness`). Without a connection the app drafts from `safety/plain-templates.json` offline. **This build has no backend URL** (it was built without `EXPO_PUBLIC_API_URL`, and release builds block plain `http`), so on a phone it always uses the templates. |
| `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `SYSTEM_ALERT_WINDOW`, `VIBRATE` | Added by the default Expo/React Native template. Jisr never requests them at runtime, so storage and overlay access are never granted. They can be removed with `android.blockedPermissions` in `app.json`. |
| `com.ai4ly.jisr.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | Internal AndroidX permission scoped to this app. |

- **No analytics SDKs**: no trackers, advertising identifiers or analytics libraries.
- **On-device history only**: chip history stays in `AsyncStorage` on the phone.
- **One-tap wipe**: the capture screen erases all stored history.
- **Guardian crisis check on-device**: typed text is screened against `safety/crisis-phrases.json`; a match blocks drafting and opens the static support card.
